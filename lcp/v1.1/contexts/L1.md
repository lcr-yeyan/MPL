# MPL Output Protocol

Return exactly one complete MPL program. Do not use Markdown fences, comments
outside the program, prose, or multiple alternatives. The program must start
with `project` (or imports before it) and end with an `export` statement.
Every top-level declaration ends with `;` except block declarations
(`track`, `section`, `arrangement`) whose closing `}` is followed by nothing.

Examples are syntax illustrations only. Never copy their project, track, clip, note or file names into a different task. For edit tasks, preserve every identifier and declaration not explicitly requested to change.


---

# MPL Grammar Reference (Language 0.3.0)

Top-level order: optional `module Name;`, optional imports, one `project`,
then declarations.

```text
project Name {
  tempo = 120 bpm;
  meter = 4/4;
  key = C major;
}

asset Piano = instrument("GrandPiano");

let M = notes span 1 whole {
  C4 @ 0 for 1/4 vel 96,
  D4 @ 1/4 for 1/4 vel 96
};

track Keys { asset = Piano; role = melodic; }

section S(1 bars) {
  clip Keys "Name" { play M; }
}

arrangement { play S; }
export midi("out.mid");
```

Rules:

- `project` needs `{}` around fields; each field ends with `;`.
- `tempo = 120 bpm;` not `tempo 120`.
- `meter = 4/4;` and `key = C major;` are exact forms.
- `asset Name = instrument("X");` or `sample("X")`.
- `let Name = expression;` ends with `;`.
- `track Name { asset = AssetName; role = melodic; }`.
- Roles: `melodic`, `bass`, `harmony`, `percussion`, `texture`.
- `section Name(N bars) { clip Track "Clip" { play Expression; } }`.
- A clip must have `play <expression>;`.
- `arrangement { play S; }`.
- `export midi("file.mid");`, `export wav("file.wav");`.
- Function: `fn f(x: Int) -> Int { return x; }`; context: `fn f() -> Fragment context meter { ... }`.
- Section meter/grouping: `section S(4 bars) meter 7/8 grouping 2+2+3 { ... }`.
- Frequency: `random(seed, index)`, no recursion.

# MPL Type Reference

- `Fragment`: notes/rests (playable).
- `Rhythm`: hit/rest events; not directly playable without pitch.
- `Chord`: `chord("Dm9")`.
- `Harmony`: `harmony span 10 whole { "Dm9" @ 0 whole for 1 whole };`
- `Voicing`: `voicing(chord, low, high, voices, inversion, maxSpacing)`.
- `Pitch`: `C4`, `D#3`, `Bb5`.
- `Duration`: `1/4`, `1 whole`, `1 bars`, `1 beats`.
- `Position`: `0`, `1/4`, `1 bars` in `@` positions (no `whole` after `@`).
- `Int`, `Number`, `Bool`, `String`, `Key`, `[T]` lists.

Context: functions that use `bars`/`beats` or metric hierarchy need
`context meter`. Functions that use `diatonicTranspose`/key need
`context key`.

Examples:

```text
let A = note(C4, 1/4, 96);          // Fragment
let R = rhythm { hit 1/8, rest 1/8 };
let V = voicing(chord("Dm9"), D3, D5, 4, 0, 12);
let X = random(7, 0);               // Number in [0,1)
```

Numeric literals are contextually typed. `note(C4, 1/4, 96)` duration is
`Duration`; `@ 1/4` is `Position`; `for 1/4` is `Duration`.

List indexing such as `pitches[0]` is NOT supported. Lists are consumed by `zip`, `cycle`, `parallel` and `for`. Extract voices with `voicingNotes(v)` and combine with `cycle`/`zip`; do not index a list.
