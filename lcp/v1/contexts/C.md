# MPL Output Protocol  Return exactly one complete MPL program. Do not use Markdown fences, comments outside the program, prose, or multiple alternatives. The program must start with `project` (or imports before it) and end with an `export` statement. Every top-level declaration ends with `;` except block declarations (`track`, `section`, `arrangement`) whose closing `}` is followed by nothing. # MPL Grammar Reference (Language 0.3.0)  Top-level order: optional `module Name;`, optional imports, one `project`, then declarations.  ```text project Name {   tempo = 120 bpm;   meter = 4/4;   key = C major; }  asset Piano = instrument("GrandPiano");  let M = notes span 1 whole {   C4 @ 0 for 1/4 vel 96,   D4 @ 1/4 for 1/4 vel 96 };  track Keys { asset = Piano; role = melodic; }  section S(1 bars) {   clip Keys "Name" { play M; } }  arrangement { play S; } export midi("out.mid"); ```  Rules:  - `project` needs `{}` around fields; each field ends with `;`. - `tempo = 120 bpm;` not `tempo 120`. - `meter = 4/4;` and `key = C major;` are exact forms. - `asset Name = instrument("X");` or `sample("X")`. - `let Name = expression;` ends with `;`. - `track Name { asset = AssetName; role = melodic; }`. - Roles: `melodic`, `bass`, `harmony`, `percussion`, `texture`. - `section Name(N bars) { clip Track "Clip" { play Expression; } }`. - A clip must have `play <expression>;`. - `arrangement { play S; }`. - `export midi("file.mid");`, `export wav("file.wav");`. - Function: `fn f(x: Int) -> Int { return x; }`; context: `fn f() -> Fragment context meter { ... }`. - Section meter/grouping: `section S(4 bars) meter 7/8 grouping 2+2+3 { ... }`. - Frequency: `random(seed, index)`, no recursion. # MPL Type Reference  - `Fragment`: notes/rests (playable). - `Rhythm`: hit/rest events; not directly playable without pitch. - `Chord`: `chord("Dm9")`. - `Harmony`: `harmony span 10 whole { "Dm9" @ 0 whole for 1 whole };` - `Voicing`: `voicing(chord, low, high, voices, inversion, maxSpacing)`. - `Pitch`: `C4`, `D#3`, `Bb5`. - `Duration`: `1/4`, `1 whole`, `1 bars`, `1 beats`. - `Position`: `0`, `1/4`, `1 bars` in `@` positions (no `whole` after `@`). - `Int`, `Number`, `Bool`, `String`, `Key`, `[T]` lists.  Context: functions that use `bars`/`beats` or metric hierarchy need `context meter`. Functions that use `diatonicTranspose`/key need `context key`.  Examples:  ```text let A = note(C4, 1/4, 96);          // Fragment let R = rhythm { hit 1/8, rest 1/8 }; let V = voicing(chord("Dm9"), D3, D5, 4, 0, 12); let X = random(7, 0);               // Number in [0,1) ```  Numeric literals are contextually typed. `note(C4, 1/4, 96)` duration is `Duration`; `@ 1/4` is `Position`; `for 1/4` is `Duration`. # Verified Canonical Examples  Example 1 鈥?basic notes:  ```text project Basic {   tempo = 120 bpm;   meter = 4/4;   key = C major; } asset PianoAsset = instrument("GrandPiano"); } } arrangement { play S; } export midi("basic.mid"); ```  Example 2 鈥?user function:  ```text project Function {   tempo = 120 bpm;   meter = 4/4;   key = C major; } asset PianoAsset = instrument("GrandPiano"); Harmony/voicing (from RC):  - `chord(name: String) -> Chord` - `chordAt(h: Harmony, at: Duration) -> Chord` - `chordAtBar(h: Harmony, bar: Int) -> Chord context meter` - `voicing(c: Chord, low: Pitch, high: Pitch, voices: Int, inversion: Int, maxSpacing: Int) -> Voicing` - `voiceLead(previous: [Pitch], c: Chord, low: Pitch, high: Pitch, maxMove: Int, maxSpacing: Int, allowCrossing: Bool) -> Voicing` - `voicingNotes(v: Voicing) -> [Pitch]` - `voicingStatus`, `voicingMovement`, `voicingCrossings`, `voicingComplete` - `commonTones(a: [Pitch], b: [Pitch]) -> [Pitch]` - `interval(a: Pitch, b: Pitch) -> Int`, `pitchClass(p: Pitch) -> Int` # MPL Semantic Contract  - All musical time is exact rational whole notes. `1/4` is a quarter note. - `bars`/`beats` resolve against the enclosing section MeterMap; all positive   bars require a bar-boundary anchor. - A Section has its own meter/grouping. Duration must end on a bar boundary. - A Clip's `play` expression is evaluated at its offset; clips on one track   overlap only if their positions overlap. - Track role is metadata; it does not change playback. - MIDI/WAV export uses the arrangement; sections play in arrangement order. - `random(seed,index)` is deterministic: same seed/index gives same number. - No recursion, no global mutation, no I/O inside MPL. - Functions are pure; a function must `return` an expression. - `context meter` is required for bars/beats/metric functions. - A program that compiles is not automatically musically correct: target   observations must be checked independently. # MPL Diagnostic Guide  Common first errors and exact fixes:  | Diagnostic | Fix | | --- | --- | | `parse-expected-equal` after `tempo` | write `tempo = 120 bpm;` | | `parse-expected-lbrace` after `project` | use `project Name { ... }`; do not quote the project name | | `parse-expected-semicolon` | add `;` after each field/let/asset/export | | `parse-expected-lparen` after section name | write `section S(1 bars) { ... }` | | `parse-unexpected-clip-item` | clip body must be `play <expr>;` (not `notes { ... }`) | | `parse-missing-play` | add `play M;` inside the clip | | `parse-unexpected-project-field` | fields are only `tempo`, `meter`, `key` | | `type-mismatch` | check expected/actual; `@` needs Position, `for` needs Duration | | `sema-unknown-symbol` | declarations must precede use; check spelling | | `sema-missing-context` | add `context meter`/`context key` | | `sema-section-overflow` | clip content longer than its section | | `limit-call-depth` | reduce nested function calls (max 32) |  Do not invent syntax such as `C4 at 0 duration 1/4 velocity 96`, `track "Keys" role melodic { ... }`, `clip Keys { notes { ... } }`, `section S { bars 1 }`, or `project "Basic"`. These are not MPL. # MPL Standard Library (Stdlib 0.3.0)  Only programs importing a module may use these exports.
