# Model-Agnostic Roadmap

日期：2026-11-25  
状态：战略路线，不绑定模型版本

## 1. 原则

1. 核心语言/编译器/运行时/Stdlib 不依赖模型。
2. 模型适配实验独立，不主导语言版本。
3. 先补音乐计算表达力与语义完整性，再做工具和生态。
4. 不以 Prompt 内容替代语言/库能力。
5. 每个阶段必须有离线可验证的验收标准。

## 2. 优先级

### P1 — 音乐计算表达力

- 列表索引/切片（受限、不可变、越界诊断）；
- Tie/持续音组；
- 完整 Tempo Map；
- 区间级音乐关系；
- Section 一等值与结构复用。

验收：新增语法/类型/运行时测试；MRP 不变；无模型调用。

### P2 — 语言语义完整性

- 函数契约（pre/post/invariant）与错误模型；
- 资源/终止语义；
- 模块可见性/命名空间；
- 确定性随机与缓存键的边界；
- 类型错误诊断一致性。

### P3 — 音乐标准库

- Arrangement 模块（section/theme/local edit）；
- Analysis 模块（关系/和声/节奏分析）；
- Production 辅助（gain/pan/automation 组合）；
- 不重复 Core 算子；只为组合/领域便利增加函数；
- 每个函数有示例、边界、契约检查。

### P4 — 音乐生产运行时

- 离线确定性渲染；
- 采样率/通道扩展；
- 处理器图性能与块大小；
- 长音频/内存边界；
- 跨平台音频后端接口（不绑定具体宿主）。

### P5 — 开发工具链

- LSP（诊断/补全/跳转）；
- Linter；
- Inspector；
- Formatter（lossless CST 后）；
- 用户测试框架；
- Project System；
- Profiler；
- Package Manager（最后）。

### P6 — 音乐生命周期与选择性控制

- Section/Clip 实例与复用；
- Frame/Diff 的局部修改；
- Preserve/Effect 契约；
- 版本化资产与渲染 manifest；
- 生命周期操作的可验证性。

### P7 — 跨后端执行

- MIDI/WAV/Reference 后端的共同语义；
- 后端能力诊断；
- 音频分析/母带目标的可移植性；
- 不伪造不可用能力。

### P8 — 系统验证与性能

- 全量回归/黄金测试；
- 资源/性能基准；
- 编译/渲染时间；
- 内存/对象数；
- 确定性哈希。

## 3. 与模型实验的关系

- `mpl_experiment`、LCP、Adaptive Context、Model Adapter、Repair 保留为独立研究方向；
- 模型实验不进入核心验收门槛；
- 不因模型表现修改语言合法性；
- 不把 held-out 参考解写入知识/上下文；
- 任何真实模型实验需预算授权，且与核心版本发布解耦。

## 4. 版本建议

| 版本 | 内容 |
| --- | --- |
| V0.5.x | 架构独立性、知识/契约、审计、工具规划 |
| V0.6 | 列表索引/Tie/Tempo Map 等语言表达力 |
| V0.7 | 契约/错误/模块语义 |
| V0.8 | Stdlib 扩展与工具链 |
| V1.0 | 稳定语言/运行时/项目系统 |

版本号仅为路线建议，不是承诺日期。

## 5. 验收指标

- 核心测试全绿（Debug/Release）；
- core-only 构建全绿，无 experiment/winhttp；
- MRP-001 稳定；
- 新增能力有独立契约/负例；
- 无模型调用也能完成编译、验证、渲染；
- 工具不重复实现前端。
