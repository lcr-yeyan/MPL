# ADR-0029：分析与验证分离

状态：已采纳（V0.3.0-rc）

## 背景

非和弦音、平行五八度、声部交叉等既可能是风格特征，也可能是错误。若默认判错，就是把
一种审美立场编码成语言语义。

## 决策

1. 三类接口：
   - Analyze：只报告事实（音程、音域、共同音、移动、交叉、区间重叠）；
   - Validate：只在显式调用时给出规则结果（voicingStatus、parallelPerfects）；
   - Construct：voicing、voiceLead、zip/cycle。
2. 默认不违规：
   - 非和弦音不报错；
   - 平行运动不报错；
   - 声部交叉不报错；
   - 重复/省略音不报错。
3. 只有程序显式查询并在控制流中据此行动时，约束才成立。
4. `parallelPerfects` 是显式分析函数，不是编译器 pass。
5. 乐器约束（音域、复音、弦品）是扩展接口，不污染通用 Pitch/Chord 语义。

## 后果

- MPL 保持“执行明确指令”的定位。
- 风格规则可由用户函数/标准库实现，而不写死进编译器。
- 验证结果可进入语义基准，但不进入审美评价。
