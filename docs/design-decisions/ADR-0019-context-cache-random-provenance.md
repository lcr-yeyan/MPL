# ADR-0019：函数上下文、缓存、随机与调用溯源

状态：已采纳（V0.3.0-alpha）

## 背景

函数如果隐式读取 Key/Meter、依赖全局随机状态或无法追踪调用，就不可复现、不可解释。需要把上下文、缓存身份与随机语义显式化。

## 决策

1. 上下文显式声明：
   ```text
   fn riff(...) -> Fragment context key, meter { ... }
   ```
   - 上下文敏感内建要求对应声明；
   - 调用带上下文的函数时，调用者必须声明同样上下文；
   - 全局表达式仍使用 Project 的 Key/Meter。
2. 缓存：
   - 键 = 函数名 + 定义版本 + Key + Meter + 实参结构；
   - 同一键返回同一 Music IR 对象；
   - 不同实参创建不同对象；
   - Clip 实例仍独立；
   - 缓存只在一次编译内有效。
3. 函数版本：
   - 由函数签名、参数、返回类型、上下文与函数体表达式结构哈希得到；
   - 语义变化必须改变版本；格式/注释不影响。
4. 随机：
   - 只提供 `random(seed, index) -> Number`；
   - 由显式 seed/index 计算，不依赖全局状态；
   - 相同 seed/index 跨平台、跨编译顺序一致；
   - 完整跨编辑稳定随机流留给 beta。
5. Trace：
   - `functions` 记录签名、上下文、版本；
   - `functionCalls` 记录调用点、实例、深度、实参、上下文、缓存命中、生成对象与算子；
   - `functionCache` 汇总 calls/hits/misses；
   - Trace 版本 4。

## 后果

- 函数结果可复现、可缓存、可追踪。
- 上下文依赖不会被隐藏；忘记声明会编译失败。
- 随机不再依赖隐式全局状态。
- 跨编译增量缓存与调用树可视化是后续工作。
