# V0.4.0-beta Architecture Review

日期：2026-11-25

## 1. 结论

V0.4.0-beta 在 V0.3.0 Final（295/295）基础上完成实验有效性基础设施，未扩张语言核心：

- Flat Event 基线适配；
- Semantic Delta V0；
- 可执行 Frame Contract；
- Observation Registry V1；
- Trusted Render Manifest；
- 参数化任务元数据与 dev/pilot/heldout split；
- A0/A1/B0/B1/C0/C1 实验运行器；
- 离线候选导入与有限修复记录。

**本轮未调用模型 API，未产生真实模型成功率。** Pilot 报告明确为未执行。

当前全量测试 **309/309**（Debug 与 Release 均通过），MRP-001 产物保持稳定。

## 2. Phase A：Regression Baseline

- V0.3.0 Final 295 项全部保留；
- 新增 14 项基础设施/负例测试；
- 无语言语义变更；
- MRP-001 仍为 10 whole、144 objects、4 modules、247 notes、921,818 帧；
- 新增 SectionRecord 属于溯源元数据，不改变音频/MIDI 输出。

## 3. Phase B：Flat Event Baseline

实现 `FlatEventDocument` / `parseFlatEvents` / `observeFlatEvents`。

- 精确有理数 `logicalExtent` / onset / duration，拒绝浮点拍数；
- Track ID、pitch（MIDI 或音名）、velocity、tempo、meter map、taskContext；
- 与 MPL 共用 Observation Registry 与 Task Verifier；
- Flat 不提供和声时间线、模块依赖、显式声部对应、clip/source range，这些观察返回
  `not-applicable`，不返回 pass/unverifiable。

覆盖率：任务 01/02/03/04/07/09 适用；05/06/08/10/11/12 不适用（原因见
`flat-event-baseline-spec.md`；10/11 含 frame）。不适用任务不进入共同成功率。

## 4. Phase C：Semantic Delta V0

实现 `computeSemanticDelta`。

- 比较 track/clip/section/harmony/符号事件/生产参数；
- 身份区分 value / generation / instance；
- ObjectId 不参与语义相等判断；
- cause 区分 direct / dependency / unknown；
- 共享依赖修改在模块粒度归因为 dependency；
- `unobserved` 明确列出 `objectIds`；不声称观察外属性不变；
- 已比较 mix、automation binding、temporal curves、asset bindings。

测试：`test_delta.cpp` 4 项，包括传递依赖归因。

## 5. Phase D：Frame Contract

- `frame.allow` / `frame.deny` 可执行；
- 逐 SemanticChange 检查；
- 未授权变化报告 object/key/property/before/after/source/cause；
- `validityStatus` / `targetStatus` / `preserveStatus` / `frameStatus` 分离；
- Flat 候选声明 frame → `not-applicable`；
- 负例：未授权 clip 修改、allowedScope none、preserve 违反、目标错误、音频绑定错误、
  预算耗尽、不支持语义、不可验证观察。

## 6. Phase E：Observation Registry V1

- 每项观察增加 id/version/input/output/unit/scope/preconditions/policy/status；
- `voice_movement` 增加显式索引对应定义与独立参考验证器；
- normalized_rhythm 明确 IOI / logical extent；
- onset_density 明确 events/whole-note；
- harmonic_timeline 规范比较按逻辑长度 + 事件序列；
- track_symbolic_events 稳定排序、保留重复；
- 音频观察支持 `expectedAudioHash`，不匹配即 unverifiable。

## 7. Phase F：Trusted Render Artifacts

`RenderArtifactManifest`：

- sourceHash / moduleHash / productionHash / assetManifestHash；
- rendererVersion / configuration / audioHash；
- `verifyRenderManifest` 重算并逐项比较；
- 任意外部 WAV 无匹配 manifest 时不得作为当前候选渲染；
- 测试覆盖 manifest 往返、音频字节改变、observation hash 不匹配。

限制：FNV 不是密码学签名；Harness 当前不自动渲染，manifest 由受控步骤生成。

## 8. Phase G：Parameterized Benchmark

- 12 个模板 ID 与固定 seed：`bench/templates.json`；
- dev/pilot/heldout：`bench/splits.json`；
- 每个 task JSON 记录 template/seed；
- 实例文件在评测前冻结；
- held-out 参考答案不进入模型上下文；
- 参考候选：baseline + 08/09/10 候选 + mastering 参考 WAV；
- 负面案例覆盖 8 类（含 not-applicable）。

限制：当前参数化是“固定 seed 的冻结实例”，不是运行时随机生成器。

## 9. Phase H：Experiment Runner

- `mpl_lab run` 支持 A0/A1/B0/B1/C0/C1；
- A 组走 Flat 验证；B/C 走 MPL 验证；
- B 组拒绝直接/间接 stdlib（检查模块闭包 `Std*`）；
- 记录 model/modelVersion/sampling/promptVersion/input/output/cache tokens/modelCalls/
  latency/repairs/error；
- 支持 `initialCandidate` 与 `final candidate`，分别记录 initialStatus/final status；
- 无模型 API 时保留离线导入；
- 不实现自动修复循环（由外部控制）。

## 10. Phase I：Factorial Design

六组共享同一 task JSON、baseline、观察、tolerance、预算与最终验证器。A 组不适用任务
返回 not-applicable；B 组被禁止使用 stdlib。首次与最终结果分别记录。

## 11. Phase J：Pilot

**未执行。** 当前环境没有模型 API 调用授权/预算。没有虚构调用、Token 或成功率。
离线 harness 可完整运行候选导入、编译、验证与记录。

## 12. 测试与冻结

- 全量 309/309（Debug & Release）；
- 新增：Flat 2、Delta 4、Render 3、Frame/Scope 3、Observation V1 1、Harness arm 1；
- 保留全部 295 项；
- MRP 输出未变。

## 13. 剩余风险

- Trusted render 无自动渲染集成；
- Parameterized benchmark 未实现运行时实例生成；
- 模型适配器未实现；
- 自动修复循环未实现；
- Flat A 组不适用任务需要人工/自动排除；
- FNV 非密码学签名。

## 14. 结论

基础设施足以公平比较 Flat 与 MPL，能识别“编译成功但音乐任务失败”，能独立验证
target/preserve/frame/validity，能拒绝未绑定音频与未授权变化。正式模型实验尚未执行。
