# MPL V0.3.0 Final Architecture Audit

日期：2026-11-25

状态：**通过，V0.3.0 语言/编译器/运行时可冻结**

基线：V0.3.0-rc（277/277）→ Final（295/295，Debug 与 Release）。

本审计不是“再跑一遍测试”。它逐项检查 RC 声明与实现是否一致，并为每个高风险语义增加
针对性测试；测试总数只是结果，不是目标。

## 1. Rhythm Continuation

### 1.1 跨周期、截取、重复

实现：

- `rotate` 把跨周期事件切分；首段保留 attack，后续段 `continuation=true`；
- `attackCount`、`onsetSet`、accent、关系算子只使用 attack；
- `repeat` 复制 continuation，并在新周期中保持与复制后的 attack 连续；
- 独立 clip 实例各自组合，不共享可变事件状态。

验证：

- `RhythmRotateWrapsAndSplitsCrossBoundaryEvents`
- `SplitContinuationDoesNotRetrigger`
- `ContinuationWithoutPredecessorIsRejected`
- `FunctionSharedValueIndependentPerformanceInstance`（既有）
- `BenchmarkIndependentRhythmObjects`（既有）

### 1.2 缺失前驱

审计发现：RC 允许构造“孤立的 continuation”（没有任何在它之前结束的 sounding event）。
这会让 `rhythmCombine` 静默丢弃一个本应持续的音，违反“不可验证近似必须诊断”。

修复：

- `Rhythm::isValid` 检查每个 continuation：
  - 必须有一个非 rest 事件在它之前结束于它的 onset；或
  - onset=0 时，有事件结束于逻辑长度（跨周期前驱）；
- 失败诊断：`rhythm-continuation-orphan`（由 `Error` 携带）。

限制：没有 tie-group id，因此验证是“存在前驱”而非“同一音高前驱”。同一 onset 上多个
不同音高的 split 仍可能被错误接受；这是已记录的 TD-39 边界，不阻塞 Final。

### 1.3 MIDI/WAV 执行

- continuation 不生成额外 MIDI note-on；
- combine 默认不为 continuation 重新触发；持续音在切分边界被截断；
- WAV 与 MIDI 使用同一 Production note 列表；
- Tie 未实现，文档明确；`retrigger(rhythm)` 是显式反向选择。

验证：

- `RhythmCombineDropsContinuation`（新增）
- `AudioPlanPlacesNotesAtExactSamples`
- `RhythmCombineDropsContinuation`

## 2. voiceLead

### 2.1 可行性与终止

- 硬约束：声部数、音域、和弦音、顺序/间距、最大移动；
- 候选按移动距离、MIDI 排序；DFS 有界；预算默认 20000；
- 每个候选节点都计数，预算耗尽立即终止；
- 无候选（音域内无和弦音、每声部无候选）→ `ProvablyUnsatisfiable`；
- 有候选但超硬约束 → `Unsatisfied`；
- 严格满足 / +1 半音容差 → 两个明确状态。

### 2.2 最优性与“全局最优”措辞

审计发现：RC 的 `budget-exhausted` 即使已经找到可行候选，也覆盖返回状态；同时文档没有
明确“找到的是预算内最佳，不是全局最优证明”。

修复：

- `Voicing` 增加 `searchComplete`；
- 预算耗尽时保留已找到的最佳候选（若有），状态为 `BudgetExhausted`，`searchComplete=false`；
- 正常结束 `searchComplete=true`；
- 文档与报告只声明“预算内最小总移动”，不声明全局最优；
- 新增语言查询 `voicingSearchComplete(v)`。

验证：

- `VoiceLeadMinimizesMovement`
- `VoiceLeadToleranceAndUnsatisfiedStatuses`
- `VoiceLeadBudgetIsExplicit`
- `VoiceLeadCrossingPolicy`
- `BenchmarkVoiceLeadingStatusTaxonomy`
- `VoiceLeadSearchCompletenessIsExplicit`（新增）

### 2.3 终止状态分类

`strictly-satisfied` / `satisfied-within-tolerance` / `unsatisfied` /
`backend-capability` / `budget-exhausted` / `provably-unsatisfiable` 六类保持独立。
`backend-capability` 当前为 API 预留，尚未由音频/指法后端实际触发（TD-43）。

## 3. HarmonyTimeline

审计：

- 事件覆盖 `[start,start+duration)`；边界右连续；
- 重叠取 start 最大者；同 start 后者优先；
- gap 返回空 chord；
- 跨和声持续音不自动切分：一个 2 whole 的 note 跨越 Dm9→G7 时仍是一个 note，起音
  使用起音处和弦；和声变化不会改变已生成 note。

验证：

- `HarmonyTimelineQueriesBoundariesAndGaps`
- `HarmonyTimelineOverlapDeterminism`
- `HarmonyAcrossVariableMeter`
- `HarmonySustainedNoteKeepsOnsetChord`（新增）

策略边界：跨和声持续音若需要重新配和声，必须由用户显式切分/重组；编译器不做隐式
reharmonization。

## 4. 模块依赖与哈希

审计发现：RC 的 `contentHash` 只覆盖模块自身源码。依赖 B 改变时：

- A 的 contentHash 不变；
- A 的 imports 路径不变；
- 但 A 的语义已经改变。

修复：

- `ModuleRecord` 增加 `resolvedHash`；
- `resolvedHash = H(sourceHash, dependencyResolvedHash...)`，按 import 顺序；
- 根模块 resolvedHash 传递覆盖全部依赖；
- Trace / compiler report / observation `module_dependencies` 输出；
- 缓存/实验可用 resolvedHash 作为模块闭包身份。

验证：

- `ModuleTransitiveHashChangesWithDependency`（新增）
- `ModuleContentIdentityAndDependencyRecords`
- `ModuleTransitiveImportsResolve`
- `BenchmarkModuleIdentityAndStdlibUse`

## 5. bars 正负位移与变拍号

Final 语义：

- 正 bars：所有（整数/分数）要求小节锚点；整数逐小节边界行走，分数按锚点小节长度；
- 负 bars：线性位移，使用锚点处小节长度；
- 因此正负不对称：从同一 anchor 走 +N bars 再 -N bars 不一定回到原点（跨拍号时）。

验证：

- `MeterMapResolvesNegativeBarsLinearly`
- `MeterMapNegativeBarsAreLinearAndAsymmetric`（新增）
- `SectionMeterChangeWithinSection`
- `SectionMetersProduceGlobalMeterMap`

文档：`docs/meter-map-spec.md`、`docs/operator-spec.md` §10.6。

## 6. InstrumentCapability

审计：

- 标准吉他 E2..E6、24 品、6 复音；
- `positions(pitch)` 每个返回位置必须 `openString + fret == midi`；
- 最高音必须由最高弦第 24 品达到；
- 音域外返回空；
- `fitsInstrument` 检查音域/复音。

验证：

- `InstrumentCapabilityGuitarBoundaries`（增强：逐位置校验、最高音可达）
- `BenchmarkAnalysisAndRelationValidation`

边界：弦/品位置不是指法求解；复音数不与弦数/手型联合验证（TD-42）。

## 7. MRP-001 Extent 复核

| 项 | 值 |
| --- | --- |
| logical extent | 10 whole = 18.181818 s |
| content extent | 9.875 whole = 17.954545 s |
| processor tail | 0 |
| 最大 instrument release | 0.25 s |
| render base | max(logical, content+release+processorTail) = 18.204545 s |
| render tail | 1.0 s |
| rendered extent | 19.204545 s |
| frames @48k | 921,818 |
| last note end | 9.875 whole |

验证：`BenchmarkMrpExtentAudit`（新增）检查 `logicalExtentSeconds`、`contentEndSeconds`、
`processorTailSeconds`、`renderedSeconds`、`totalFrames` 的关系；WAV 实测 921,818 帧。

结论：logical/content/processor-tail/render extent 四者没有被混用；尾部包含 instrument
release 与显式 render tail。

## 8. 诊断与 Backend Contract

- 前端诊断：稳定 code、SourceSpan、expected/actual、related；
- 后端不支持策略：`Strict` 报错、`Approximate` 警告并继续、`Ignore` 跳过；
- `audio-tail-capped`、`midi`、`meter-metric-duration`、`rhythm-continuation-orphan` 等
  code 保持稳定；
- 不支持的语义不会静默变成近似值；近似必须带 warning。

验证：

- `BenchmarkUnsupportedMidBarMeterIsDiagnosed`
- `UnsuitableTemporalBackendUsageIsDiagnosed`（既有）
- `MaxTailIsCappedWithDiagnostic`（既有）

## 9. 结论

- RC 的 277 项全部保留；
- 新增 18 项针对性回归与基础设施测试；
- 未发现需要重构编译器核心的缺陷；
- 两处实际语义缺陷已修复：孤立 continuation、模块传递哈希；
- 一处 API 语义澄清：voiceLead 的 `searchComplete` 与“非全局最优”措辞。

**V0.3.0 可以冻结。**
