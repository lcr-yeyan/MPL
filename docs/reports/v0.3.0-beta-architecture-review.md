# MPL V0.3.0-beta 架构审查

日期：2026-11-25

审查基线：V0.3.0-alpha（158/158 测试通过）

范围：Rational 时间模型、Meter Map 数据容器、四种时间类型、Duration/Position、Section/Clip
时间解析、MIDI 拍号事件、Temporal IR 时间域、函数缓存与传递依赖、Music Value / Function
Invocation / Performance Instance 的身份区别。

结论先行：现有 Rational + Music IR 依赖图 + Typed HIR 足以承载 V0.3.0-beta，不需要重写
Temporal IR 或引入新运行时。实际缺陷集中在四处：

1. 拍号只有全局 `Meter`，`ProductionIR::meterMap` 虽有容器但只能写入一个初始事件；
2. `bars` / `beats` 在 Sema 阶段按全局拍号折叠为全音符常量，无法表达“起点依赖”；
3. 没有独立 Rhythm 值类型，节奏只能以 Fragment 的 offset/duration 集合存在；
4. 函数缓存键只含全局 Key/Meter 字符串，不含调用位置的节拍上下文。

因此本阶段修改是**局部扩展**：新增 MeterMap / Rhythm 两个值系统，扩展前端与 Lowering
的上下文解析，不改变 Music IR 的 Fragment 求值模型，不改变 Temporal IR 的结构。

## 1. Rational 时间模型

现状：

- `Rational` 以 int64 分子/分母表示，构造即约分；
- 加减乘除带溢出检查，乘法先交叉约分；
- 比较使用连分数算法，避免交叉相乘溢出；
- 所有音乐时间以全音符为单位。

结论：保留。缺陷与修改：

- **无显式容量契约**：`lcm` 与周期运算会产生大于音乐需要的分子/分母。本阶段在 Rhythm
  与 MeterMap 层增加显式上限（见 §9），不修改 Rational 本身。
- **缺少 `lcm` / 整除判断**：新增 `RationalMath` 辅助（`rationalLcm`、`isIntegerMultiple`），
  以 `__int128` 预检并返回 `std::optional`，避免异常穿透到用户程序。
- Rational 的 0 分母与溢出仍抛 `mpl::Error`，由前端转为诊断。

## 2. Meter Map 数据容器

现状：

- `Meter` 只有 numerator/denominator 与 `barLength()` / `beatLength()`；
- `ProductionIR::meterMap` 是 `vector<MeterEvent>`，但 `Compiler::compile` 只 push 一个
  `Position{}` 事件；
- `MidiBackend` 已经能序列化多个 `MetaTimeSignature` 事件，缺的是上游数据；
- `Project` 只保存一个 `Meter`，`MusicIR` 也只保存一个 `Meter`；
- `SectionDecl` 与 `ClipDecl` 没有拍号字段。

实际缺陷：

1. 没有“绝对位置 → 小节/拍”的精确双向转换；
2. 没有拍号变化边界校验，非法事件（负位置、逆序、拍中变化）无法在写入时拒绝；
3. `bars` 单位在 Sema 折叠，Section 起点与拍号无关，变拍号下必然错误；
4. 没有节拍分组（2+2+3）与层级查询；
5. Production 的 meter event 没有 grouping 字段，Trace 无拍号变化记录。

必要修改（不重写 IR）：

- 新增 `MeterMap` 值对象：有序事件、初始事件、精确 `Position <-> MetricPosition` 转换、
  小节边界与拍号查询、严格校验；
- `MeterEvent` 增加 `MetricGrouping` 与 `explicitGrouping`；
- `Project` 持有 `MeterMap`；`Compiler` 把它完整写入 Production IR；
- Section 声明自己的拍号与局部 MeterMap，Arrangement 按播放顺序拼接为全局 MeterMap。

**Meter 变化必须落在小节边界**。这是本阶段的硬约束：允许 Section 内变拍号，但 `at`
位置必须等于局部小节起点。理由：只有这样才能定义全局小节编号与 MIDI 拍号事件的稳定
位置；拍中变拍号需要“小节内拍号”这一额外维度，超出本阶段范围，遇到时给出诊断而不是
近似。

## 3. 四种时间类型

现状：

- `MusicalTime` 包装 `Position`；
- `RelativeTime` 是 [0,1] 有理数；
- `PhysicalTime` 是 double 秒；
- `SampleTime` 是 int64 采样序号；
- Temporal IR 只求值 Musical / Relative 域。

结论：保留，不新增第五种时间类型。补充：

- `MetricPosition`（小节 + 小节内拍偏移）不是时间轴类型，而是**同一绝对 MusicalTime 的
  坐标表示**，放在 MeterMap 模块，不进入 `TimeDomain` 枚举；
- `MetricDuration`（N 小节 / N 拍）是**依赖锚点位置的长度描述**，不是绝对时值；只有在
  给定 MeterMap 与锚点后才折叠为 `Duration`；
- 语言层 `bars` / `beats` 字面量携带“度量单位 + 数量”，Lowering 在正确的 MeterMap 与
  锚点下解析；`whole` 与裸有理数仍是绝对时值。

这条区分是本阶段“bars 单位起始位置依赖”的实现基础，也是修复 §2 缺陷 3 的方式。

## 4. Duration 与 Position

现状：

- 两者都是全音符有理数的薄包装；
- `Duration::fromBars(bars, meter)` / `Position::fromBars(...)` 接受单一 `Meter`；
- 语言层 `bars` / `beats` 在 Sema 折叠。

缺陷：`fromBars` 的签名诱导“拍号是全局常量”的使用方式；变拍号下必须由 MeterMap +
锚点解析。

修改：

- 保留 `Duration` / `Position` 不变；
- 新增 `MetricDuration { Rational amount; MetricUnit unit; }` 与
  `MeterMap::resolveDuration(anchor, metric)` / `resolveOffset(anchor, metric)`；
- 旧的 `fromBars` / `fromBeats` 继续存在，仅用于单一拍号上下文（测试与后端），
  语言前端不再直接调用；
- 保留 `Duration` / `Position` 的可加性与精确比较，不引入浮点中间值。

## 5. Section 与 Clip 的时间解析

现状：

- `SectionDecl::duration` 在 Sema 用全局 Meter 折成全音符；
- `ClipDecl::at` 同样；
- Lowering 先按声明顺序 lower 每个 Section，Arrangement 再累加 `cursor`；
- Clip 起始 = `cursor + clip.offset`；
- 同一 Section 可被多次 play，但内容只 lower 一次，实例 id 按 occurrence 区分。

缺陷：

1. Section 长度在变拍号下取决于起点，而现状在 Sema 已折叠；
2. 同一 Section 重复播放时，若内容依赖绝对拍号上下文，lower 一次会得到错误结果；
3. Clip 的 `bars` 偏移相对 Section 起点，但现状按全局拍号解释。

修改（明确规则）：

- **Section 自带局部 MeterMap**：`section A(4 bars) meter 7/8 grouping 2+2+3 { ... }`；
- Section 内可用 `meter 5/8 at 2 bars grouping 2+3;` 声明局部变拍号；
- Section 内容（duration、clip at、play 表达式）在**局部坐标**中 lower 一次，锚点为局部 0；
- Section 无拍号声明时使用 project 的初始拍号，而不是继承前一段落。这样内容与播放位置
  无关，可安全重复播放，也避免“同一 Section 两次播放产生不同 IR”的隐藏不确定性；
- Arrangement 播放时，把 Section 的局部 MeterMap 平移到全局 cursor，拼接为全局 MeterMap；
  `cursor` 前进量 = 该 Section 在其局部 MeterMap 下 `duration` 的精确长度；
- 全局小节编号连续：Section 长度必须是整数小节（否则诊断），保证下一 Section 从小节
  边界开始；
- Clip 的 `at` 在 Section 局部 MeterMap 下解析，必须非负；允许不对齐小节，但 `bars`
  作为单位时锚点必须是小节起点（否则诊断 `meter-bars-off-grid`）。

## 6. MIDI 拍号事件

现状：

- `MidiEventKind::MetaTimeSignature` 已实现；
- `buildTracks` 遍历 `production.meterMap` 并写入 conductor track；
- `tickAt` 用 PPQ 精确换算，非整 tick 会抛错。

缺陷：只有上游数据缺失；分组没有导出；没有验证拍号事件的 tick 对齐。

修改：

- Production IR 的 `meterMap` 携带 grouping；
- Compiler 写入完整 MeterMap；
- MIDI Backend 为每个事件输出 `MetaTimeSignature`，并检查 tick 精确性；
- MIDI 没有标准的“节拍分组”元事件，分组写入 Trace / Production JSON，不伪造 MIDI
  事件；`describe()` 以 `meter 7/8 (2+2+3)` 形式展示，便于测试；
- Tempo Map 保持独立，本阶段不做变速。

## 7. Temporal IR 时间域

现状：

- Musical / Relative 曲线可求值；Physical / Sample 域保留边界；
- 曲线 extent 与 Automation 绑定；
- 时间域与拍号无关。

结论：**不需要修改**。Temporal IR 的时间轴是绝对 MusicalTime；变拍号只影响语言层
`bars`/`beats` 的解析与 Production 时间线，不改变曲线采样。本阶段不新增音频速率曲线，
不把 MeterMap 塞进 Temporal IR。

## 8. 函数缓存与传递依赖

现状：

- 缓存键 = `fn:name:v<version>:k<key>:m<meter>|args`；
- 命中返回同一 Music IR 对象 id；
- Trace 记录 `functions` / `functionCalls` / `functionCache`；
- 递归在 Sema 拒绝；调用深度/次数有硬限制。

实际缺陷：

1. 缓存键只有单一 Meter，没有调用锚点；变拍号下同一函数在 7/8 与 5/8 段落会错误共享；
2. 上下文依赖只在直接函数上检查，但传递性已经由 Sema 的 `callGraph_` 与调用方
   `context` 检查覆盖（有测试）；缺的是缓存键对“度量上下文身份”的建模；
3. `functionCalls` 记录 `contextMeter` 为全局拍号字符串，无法区分局部 MeterMap。

修改：

- 引入 `MetricContext { MeterMap id, anchor }`；Lowering 维护上下文栈；
- 函数缓存键加入 `mc<mapId>@<anchor>`，不同度量上下文产生不同对象；
- Trace 的函数调用记录 `contextMeter`（锚点处拍号）与 `metricContext`（map id + anchor）；
- Music Value（`ObjectId`）、Function Invocation（调用实例序号 + 调用点）、Performance
  Instance（`InstanceId`）继续分离：
  - 同参同上下文函数调用共享 Music Value；
  - 每次调用仍记录独立 invocation；
  - 每个 Clip 仍是独立 Performance Instance，拥有独立表情/自动化，不因共享 Music
    Value 合并；
- 函数定义版本（结构哈希）变化时，缓存键变化，旧定义不会被复用；同编译内不存在跨
  版本命中。跨编译持久缓存仍不在本阶段范围（见技术债务）。

## 9. 容量与溢出契约

新增的周期/代数运算必须防止无界展开：

- Rational 分子/分母上限：`10^9`；
- Rhythm 事件上限：4096；
- `repeat` 次数上限：256；
- `subdivide` 分割数上限：64；
- 周期 LCM 上限：分子/分母 `10^9`，超出返回诊断 `rhythm-period-overflow`；
- 所有失败返回诊断，不抛未捕获异常到用户程序。

## 12. 实施结果（回填）

审查时的两个开放问题已按以下方式决定：

1. **Rhythm 的 IR 形态**：采用“Music IR 值节点”，与 Fragment 共用 `ObjectId` 空间，
   不建立独立 `RhythmIR`。理由：复用依赖图、失效、缓存与 Trace；避免第二套 id 空间。
   `MusicNode` 同时可缓存 Fragment 与 Rhythm；`evaluate` 与 `evaluateRhythm` 分型。
   见 ADR-0021。
2. **syncopate 的显式节拍上下文**：`SyncopateNode` 增加可选 `MeterMap + anchor`；
   Lowering 始终传入当前 MetricScope。旧的无 Map 重载保留给直接使用 MusicIR 的调用方。
   见 ADR-0022/0025。

实施中还确认：

- `MeterMap` 的 `eventAt` 必须对“恰好落在事件起点”的位置返回该事件（右连续），
  否则 `barLengthAt` 与 `toMetric` 在变拍号边界会取到前一个拍号；
- grid 关系与 `quantize` 必须共用“最近 grid、平局向上”的规则，否则 `1/16` 起音在
  `1/8` 网格下会与前一声部错位；
- 函数调用链在 Debug 下的递归栈帧较大，Rhythm 字面量与算子的 lowering 被拆到独立
  成员函数，避免 32 层调用链栈溢出。这不是语义限制，而是实现稳健性修正。

最终测试为 237/237（Debug 与 Release），新增 79 项。
