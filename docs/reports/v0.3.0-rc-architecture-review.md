# MPL V0.3.0-rc 架构审查

日期：2026-11-25

审查基线：V0.3.0-beta（237/237 测试通过）

范围：Beta 语义复核（bars 锚定、度量坐标/小节时长、Rhythm 跨周期切分、MIDI grouping、
不支持语义诊断、函数传递依赖）；Pitch/Harmony 类型；Harmony Timeline；音乐对象组合；
声部连接；音乐关系分析；最小模块系统；乐器能力边界。

结论：Beta 的架构仍成立。RC 不重写 Rational、Music IR、Temporal IR 或函数求值模型；
实际修复集中在四处，其余为增量类型与前端/链接能力：

1. Beta 中正分数 bars 在非小节锚点可解析，而正整数 bars 要求小节起点，语义不一致；
2. Rhythm 跨周期切分把持续音切成多个 attack，改变了重新触发语义；
3. 缺少 Chord / PitchClassSet / Voicing / HarmonyTimeline 与声部连接搜索；
4. 全局 SymbolTable 无模块/导入/公开符号能力。

## 1. Beta 语义复核

### 1.1 正整数、负整数及分数 bars

现状缺陷：

- 正整数 `N bars` 逐小节边界行走，anchor 必须是小节起点；
- 正分数如 `1/4 bars` 直接按 anchor 处小节长度缩放，anchor 不是小节起点也成功；
- 负 bars 线性缩放。

同一“bars”单位在符号/锚点上出现不一致。RC 决策：

- **所有正 bars（整数或分数）都锚定在小节边界**；非小节 anchor 报 `meter-metric-duration`。
- 正整数逐小节行走，可跨拍号变化；正分数按 anchor 处小节长度线性缩放。
- 负 bars 仍为线性度量位移（用于 `shift` 等），不反向跨拍号行走。
- 这一规则在 `docs/meter-map-spec.md` §5 更新。

### 1.2 度量坐标移动 vs 局部小节时长

区分：

- `MeterMap::positionOfBar(n)` / `barIndexAt`：度量坐标移动，回答“第 n 小节在哪里”；
- `MeterMap::resolveDuration(anchor, N bars)`：局部小节时长，回答“从 anchor 起 N 小节有多长”；
- Section 时长必须是局部小节时长的结果，并额外验证终点落在小节边界（`section-not-bar-aligned`）。

代码不把两者合并：Section 时长仍通过 `resolveDuration` + `isBarStart` 双检查。

### 1.3 Rhythm 跨周期切分与 Retrigger

Beta 的 `rotate` 把跨周期事件切成多段，`rhythmCombine` 对每段都生成一个 note，
等于把一个持续音变成多个 attack。RC 修复：

- `RhythmEvent` 增加 `continuation`；
- 切分第一段保留 attack 状态，后续段为 continuation；
- `attackCount`、onset 集合、accent、关系算子都只使用 attack；
- `rhythmCombine` 默认不 retrigger continuation（Split：持续音在周期边界被截断，不重新触发）；
- 新增 `retrigger(rhythm)` 显式清除 continuation（Retrigger）；
- **Tie 未实现**：MPL 不声称支持跨周期连音线；需要时用 `retrigger` 或改变周期长度。
  这是明确的能力边界，不是隐藏近似。

### 1.4 MIDI 拍号事件与 MetricGrouping

- MIDI `FF 58` 只能表达分子/分母，不能表达 2+2+3；
- grouping 写入 Production IR、Trace 与 `MidiBackend::describe()`；
- 不伪造 MIDI 元事件，也不声称 MIDI 已表达 grouping；
- 时间签名事件在 PPQ 下必须精确；否则报 `midi` 错误。

### 1.5 不支持度量语义的诊断

| 语义 | 诊断 |
| --- | --- |
| 拍中变拍号 | `meter-change-invalid` |
| bars 非小节锚点 | `meter-metric-duration` |
| Section 长度不对齐 | `section-not-bar-aligned` |
| 非整数倍 realign | `rhythm-realign` |
| 周期溢出 | `rhythm-period-overflow` |
| 负 onset 组合 | `rhythm-pitch` |
| grouping 非法 | `invalid-meter-grouping` / `sema-meter-grouping` |

### 1.6 函数传递依赖、缓存与调用身份

复核结论：

- 缓存键包含函数版本、Key、metricContext 与实参；
- 同参同定义同上下文共享 Music Value；
- 调用实例、Clip InstanceId 与 Music Value 仍分离；
- 改变被调用函数定义会改变调用链结果；
- 无关 Section 的拍号变化不改变另一 Section 的结果；
- 新增模块后，库函数的私有名被 mangle，公开名进入全局命名空间；函数版本仍按函数体结构哈希。

Beta 报告的 18.181818 s / 921818 帧已复核：RC 的 MRP-001 仍为 10 whole notes、132 BPM、
48 kHz、921,818 帧。

## 2. Pitch / Harmony 类型审查

现有：`Pitch`（带拼写与 MIDI 编号）、`Interval`（半音）、`ScaleDegree`（语言类型）、
`Key`（大调/自然小调）、`harmonize` 算子。缺少：PitchClass、PitchClassSet、ChordSymbol、
Voicing、HarmonicFunction、HarmonyTimeline。

RC 决策：

- 复用 `Pitch`/`Interval`/`Key`；新增 `PitchClass`、`PitchClassSet`、`ChordSymbol`、
  `Voicing`、`HarmonyTimeline`。
- `ChordSymbol` 保存显式 interval set，避免把“和弦质量枚举”当成封闭理论；
- 转位、扩展音、重复音、省略音、非调内音均有明确规则（见 spec）；
- 不实现完整微分音/任意调律；MIDI 0..127 只是编码边界，不定义音乐理论范围；
- `HarmonicFunction` 只保留枚举接口，不在自动分析中强行标注功能。

## 3. Harmony Timeline

- 独立值，事件 `[start, start+duration)`；
- 允许重叠与空白；跨小节/变拍号位置由 Lowering 的 bars 解析决定；
- `eventAt`：覆盖该时刻的事件中 start 最大者；同 start 取后声明者（确定性）；
- `eventsAt` 返回全部覆盖事件；
- 边界右连续；gap 返回空 chord；
- 逻辑长度可显式延长；
- Music IR 中为 `harmony-literal` 与 `harmony-query` 节点，参与依赖、缓存与 Trace。

## 4. 音乐对象组合

组合不需要新的通用“生成器”：

- `chordAt` / `chordAtBar` 选择和声；
- `voicing` / `voiceLead` 生成具体音高；
- `zip` / `cycle` 把 Rhythm 与音高组合；
- 用户函数按小节循环，完成“节奏 + 和声 + 音高策略”。

因此 RC 只新增领域内建（chord/voicing/query），不引入通用约束求解器。

## 5. 声部连接

- 硬约束：声部数、音域、和弦音、顺序/间距（可选）、最大移动；
- 优化：总移动距离最小；
- 确定性：候选按移动距离、再按低到高 pitch 字典序；
- 有界搜索：预算耗尽返回 `BudgetExhausted`，不声明“无解”；
- 无候选且枚举完整：`ProvablyUnsatisfiable`；
- 超过最大移动但在 +1 半音容差内：`SatisfiedWithinTolerance`；
- 有候选但违反硬约束：`Unsatisfied`；
- 后端能力不足（如音域超出 MIDI/乐器）：`BackendCapability`。

## 6. 关系分析

Analyze / Validate / Construct 三类接口：

- Analyze：interval、pitchClass、pitchRange、chordContains、commonTones、voiceDistance、
  voiceCrossings、noteOverlap、fragmentRange；
- Validate：voicingStatus、voicingComplete、parallelPerfects（显式调用才构成违规）；
- Construct：voicing、voiceLead、zip/cycle、stdlib 组合函数。

非和弦音、平行运动等不在默认情况下构成错误；只有程序显式调用验证接口并据其结果行动时
才成为约束。

## 7. 最小模块系统

- 文件级模块：`module Name;`、`import "path";`、`export fn/let/curve`；
- 链接阶段合并 AST，私有符号 mangle，公开符号去重；
- 循环导入、缺失导入、导出冲突、模块内不支持声明均有诊断；
- 模块内容哈希与直接导入路径进入 Trace；
- 标准库为普通 MPL 模块文件，不引入包管理器、动态模块或任意 I/O。

## 8. 乐器能力边界

新增 `InstrumentCapability`：

- 音域、复音数、开放弦、品数；
- 弦/品位置查询；
- 不改变 Pitch/Chord 的通用语义；
- 不实现完整指法求解器或物理建模。
