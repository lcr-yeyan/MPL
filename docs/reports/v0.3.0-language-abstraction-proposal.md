# MPL V0.3.0 语言抽象设计提案

状态：提案（Phase 2 结束后启动）

目标：让音乐创作知识可以程序化表达，而不是继续增加底层音频功能。

## 1. 定位

V0.2.0 已具备：

- 精确音乐时间、Music/Temporal/Production IR；
- 文本前端、类型/单位/时间域检查；
- 独立信号图、DSP、分析、母带与生产反馈。

V0.3.0 不扩展音频设备、插件宿主或空间音频。它解决“如何复用、参数化与组织创作知识”：

- 用户定义函数；
- 局部作用域；
- 模块与导入；
- 音乐对象参数化；
- 可复用创作算法；
- 稳定随机流；
- 音乐生成标准库；
- 函数调用溯源；
- 递归、循环与计算资源限制。

## 2. 用户定义函数

### 2.1 语义

函数是纯音乐计算的可复用单元：

```text
fn motif(root: Pitch, degrees: [Int], rhythm: Duration) -> Fragment {
  ...
}
```

- 默认纯函数：相同输入产生相同输出；
- 不允许隐式读写全局上下文；
- 需要 Key/Meter 时显式传参，或声明 `context(key)`；
- 返回类型必须显式；
- 不允许在函数内声明 Track/Section/Export 等生产结构。

### 2.2 类型

- 参数与返回值使用现有类型系统：Fragment、Curve、Duration、Position、Pitch、Int、Number、Asset、Processor 等；
- 泛型暂不引入；
- 函数值（higher-order）暂不引入，但保留语法位置。

### 2.3 诊断

- 参数数量/类型/单位错误；
- 返回类型不匹配；
- 未解析调用；
- 递归深度超限；
- 调用图环路（若允许递归，需显式 `rec` 标记）。

## 3. 局部作用域

```text
fn verse(...) -> Fragment {
  let a = ...;
  let b = stretch(a, 2);
  sequence(a, b)
}
```

- `let` 默认为不可变绑定；
- 作用域按块嵌套；
- 内层可遮蔽外层，但产生警告；
- 不允许在函数内定义 Track/Curve 等全局声明；
- 名称解析先局部、后模块、后导入。

## 4. 模块与导入

```text
module drums {
  export fn basicBeat(...) -> Fragment { ... }
}

import drums;
import "library/strings.mpl" as strings;
```

- 模块是命名空间与编译单元；
- `export` 控制可见性；
- 导入循环必须被拒绝；
- 模块初始化不得有副作用；
- 版本与内容哈希进入 Trace，保证可复现；
- 资产声明可以跨模块引用，但必须显式导入。

## 5. 音乐对象参数化

参数化的对象：

- 动机、和声进行、节奏型、配器模板、混音模板；
- 参数可以是音高、音级、时值、曲线、整数、布尔；
- 不接受“任意字符串命令”作为参数；
- 参数约束使用类型与范围，不引入完整约束求解器。

示例：

```text
fn progression(roots: [Pitch], barsPerChord: Duration) -> Fragment { ... }
fn padVoicing(source: Fragment, degrees: [Int]) -> Fragment { ... }
```

## 6. 可复用创作算法

允许的算法：

- 序列/并行/镜像/缩放等确定性变换；
- 基于音级/节拍/和声的上下文算法；
- 受控随机选择；
- 图案替换、节奏位移、声部排列；
- 用户定义的高层组合。

不允许：

- 隐式风格模型；
- 在线学习；
- 黑盒生成；
- 依赖外部服务的生成；
- 无种子随机。

## 7. 稳定随机流

```text
fn humanize(seed: Int, amount: Curve) -> Curve
```

规则：

- 每个随机调用必须携带稳定 seed 或从显式 seed 派生；
- 随机流不得依赖编译顺序、线程调度或系统时间；
- 同一 seed + 同一调用点 + 同一输入 → 同一结果；
- 调用点身份进入 Trace（模块、函数、调用序号）；
- 禁止全局可变随机状态。

## 8. 音乐生成标准库

建议的最小标准库：

| 模块 | 内容 |
| --- | --- |
| `std/rhythm` | 节奏型、切分、律动位移、概率门限 |
| `std/harmony` | 和弦构造、声部进行、音级排列 |
| `std/melody` | 动机变形、模进、装饰、轮廓控制 |
| `std/form` | 段落重复、对比、过渡 |
| `std/orchestration` | 音区分配、重复音、声部交叉检查 |
| `std/mix` | 通道条模板、Send 模板、母带目标模板 |

标准库必须是纯函数、可测试、无隐藏上下文；每个算法提供参考输出与边界诊断。

## 9. 函数调用溯源

每次调用记录：

- 模块与函数名；
- 调用点 SourceSpan；
- 实参摘要；
- 返回对象 id / 曲线 id；
- 递归深度与迭代次数；
- 随机 seed。

Trace 用于：

- 复现一次生成；
- 定位“为什么出现这个音/这个片段”；
- 比较两次编译的差异；
- 性能与资源分析。

调用溯源不得改变音乐语义。

## 10. 递归、循环与资源限制

必须预设硬限制：

- 最大递归深度（建议 64）；
- 最大循环迭代次数（建议 1,000,000）；
- 单次编译最大对象数；
- 最大曲线节点数；
- 最大编译时间（可由 CLI 配置）。

诊断：

- `limit-recursion-depth`
- `limit-loop-iterations`
- `limit-object-count`
- `limit-compile-time`

禁止无限循环与无界生成；所有失败必须给出调用栈摘要。

## 11. 分阶段实施建议

1. 局部作用域 + 用户函数（纯函数、显式类型、无递归）；
2. 模块/导入 + 可见性 + 循环导入诊断；
3. 标准库 `rhythm` / `harmony` / `melody`；
4. 稳定随机流 + 调用溯源 Trace；
5. 受控递归与循环 + 资源限制；
6. 生产模板（混音/母带目标）作为库函数，而非新语法。

## 12. 非目标

- 通用编程语言；
- 通用约束求解器；
- 实时脚本；
- 插件/设备管理；
- AI/LLM 生成；
- 情绪、审美、Taste；
- 完整 DAW。

## 13. 验收方向

- 同一函数在不同模块中可复用；
- 同一 seed 跨平台、跨编译顺序产生相同输出；
- 调用 Trace 可以解释任意生成片段的来源；
- 资源限制可触发且诊断清晰；
- 标准库算法有固定参考输出；
- 不引入隐式全局状态与不可复现行为。
